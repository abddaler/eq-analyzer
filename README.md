# EQ Scope

Мобильный анализатор спектра (RTA) с подсказками по эквализации. PWA:
Vite + TypeScript + React, весь DSP — свой, без внешних библиотек.

Приложение даёт подсказку **относительно выбранной целевой кривой**, а не
«правильный» ответ. Достоверность каждой подсказки показывается явно;
последнее слово — за ушами звукорежиссёра.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm test           # юнит-тесты DSP на синтетических сигналах
npm run check      # типы + тесты + линтер
npm run e2e        # смоук-тесты в браузере (микрофон — фейковое устройство Chromium)
npm run build      # прод-сборка в dist/
```

Микрофон работает только в защищённом контексте: `localhost` или HTTPS.
Для проверки с телефона в локальной сети запускайте `npm run dev -- --host`
и открывайте по HTTPS (иначе браузер не отдаст микрофон).

## Структура

```
src/audio      захват звука: интерфейс AudioSource, веб-реализация,
               AudioWorklet, кольцевой буфер, запись WAV
src/dsp        FFT, окна, октавные полосы, усреднение, взвешивание,
               калибровка, детектор пиков
src/analysis   целевые кривые, зоны, генерация подсказок
src/generator  генератор тестовых сигналов
src/ui         экраны и графики (Canvas 2D)
src/storage    IndexedDB
src/i18n       словари ru/en (типизированы: пропуск строки — ошибка сборки)
src/data       ISO-полосы, целевые кривые, профили микрофонов
tests          юнит-тесты DSP и анализа
```

## Как рождается подсказка

1. Берётся длинное скользящее среднее по полосам (10–60 с) — по мгновенному
   спектру решения о миксе не принимают.
2. Целевая кривая проецируется на полосы и **сдвигается по уровню** так, чтобы
   её среднее в 500 Гц – 2 кГц совпало с замером: сравнивается форма, а не
   громкость.
3. Полосы, которым нельзя верить, выбрасываются: вне диапазона микрофона или
   меньше 10 дБ над замеренным порогом шума.
4. Соседние полосы с отклонением одного знака объединяются в область; область
   попадает в вывод, только если где-то внутри отклонение ≥ 3 дБ.
5. Центр области — среднее геометрическое, взвешенное по отклонению; ширина в
   октавах даёт Q = 2^(N/2)/(2^N − 1). Область шириной в октаву → Q ≈ 1.4.
6. Коррекция = −(отклонение × 0.65), жёсткий предел ±6 дБ. Одновременно
   показывается не больше 4 подсказок, по убыванию значимости.
7. Карточки обновляются не чаще раза в 2.5 с и только если реально изменились.

## Двухканальный режим

Одноканальный RTA не отделяет систему от музыки: что играет группа, то он и
меряет. Сигнал с пульта как референс плюс микрофон дают передаточную функцию —
АЧХ системы и зала отдельно от программы, плюс фазу и когерентность.

Задержка между каналами ищется через GCC-PHAT: обычная кросс-корреляция
цепляется за самое громкое (обычно низ) и размазывает пик на миллисекунды,
а выбеливание каждого бина делает пик острым и почти не зависящим от уровня —
именно это позволяет работать по музыке, а не только по шуму.

Когерентность показывается всегда и решает, верить ли остальному: там, где
она ниже 0.5, АЧХ и фаза рисуются тускло.

Режиму нужен стерео-вход (USB-аудиоинтерфейс: канал 1 — выход пульта, канал 2 —
измерительный микрофон). Встроенный микрофон телефона даёт один канал, и
приложение честно говорит, что режим не включится. Захват уже умеет два
канала, поэтому нативная обёртка для этого не обязательна — но насколько
стабильно браузер отдаёт стерео с USB-интерфейса на конкретном телефоне,
покажет только проверка на устройстве.

## Прогрев захвата

Открытие микрофона не мгновенное: первые доли секунды ОС отдаёт тишину или
поднимает вход по рампе. Если эти кадры попадают в усреднение, уровень потом
ползёт вверх ровно столько, сколько длится окно — в комнате, где ничего не
менялось.

Поэтому движок ничего не измеряет, пока вход не ожил (первый кадр громче
−100 dBFS — это не тихий зал, это ещё не открывшийся микрофон) и не прошла
секунда после этого. Короткие усреднители работают сразу, чтобы на экране
была картинка, но в конце прогрева сбрасываются, а длинное окно, peak hold,
Leq и детектор резонансов начинают с уже устоявшегося входа. На экране в это
время написано «прогрев».

## Соглашения по уровням

Это самое важное место в проекте — если перепутать нормировку, анализатор
начнёт тихо врать.

* **0 dBFS** — синус с пиковой амплитудой 1.0, то есть средний квадрат 0.5.
  Синус −20 dBFS имеет пиковую амплитуду 0.1.
* `power[]` из `SpectrumAnalyzer` — **средний квадрат, нормированный по
  энергии** (`2|X|² / (N·Σw²)`). Сумма по полосе или по главному лепестку тона
  даёт истинный средний квадрат. Именно это нужно для октавных полос.
* Для **отображения отдельного бина FFT** энергетическая нормировка занижает
  тон на `10·log10(ENBW)`, поэтому у `binDisplayDb()` есть поправка на ENBW
  окна. Для сумм по полосам её применять нельзя.
* Энергия полосы считается **суммой мощностей бинов** с дробным учётом краевых
  бинов (интеграл спектральной плотности), никогда не средним в децибелах.

## Производительность

Замер в headless Chromium (десктоп, не телефон): 60 кадров/с на экране
водопада, куча JS 8–10 МБ и без роста за 45 секунд непрерывной работы.
На устройстве те же цифры видно на экране диагностики — карточка
«Производительность» показывает кадры экрана, кадры анализа и память.

## Деплой

Сайт умеет жить и в корне домена, и в подкаталоге: путь задаётся переменной
`BASE_PATH` на сборке (по умолчанию `/`). Все ссылки в манифесте,
сервис-воркере и HTML относительные, поэтому PWA и офлайн работают в обоих
случаях.

### GitHub Pages

Workflow `.github/workflows/deploy.yml` собирает проект и публикует `dist`.
В репозитории нужно один раз переключить источник:

**Settings → Pages → Build and deployment → Source = GitHub Actions.**

Без этого GitHub Pages отдаёт репозиторий как есть — то есть исходный
`index.html`, который ссылается на `/src/main.tsx`, и в браузере получается
пустой экран. Проектный сайт живёт по адресу `https://<user>.github.io/<repo>/`,
поэтому workflow собирает с `BASE_PATH=/<repo>/` и кладёт рядом `404.html`
и `.nojekyll`.

### Cloudflare Pages

Настройки проекта:

| Параметр | Значение |
|---|---|
| Framework preset | None (или Vite) |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | пусто (корень репозитория) |
| Production branch | ветка, в которой лежит код |

Версия Node задана файлом `.node-version` (22): Vite требует
`^20.19 || >=22.12`, а по умолчанию Pages может поднять Node 18 — тогда
сборка падает ещё на установке зависимостей. Если версия всё равно не та,
продублируйте её переменной окружения `NODE_VERSION = 22` в настройках
проекта.

`public/_headers` и `public/_redirects` уже настроены (SPA-фоллбэк,
`no-cache` для `index.html` и `sw.js`, вечный кеш для хешированных ассетов)
и попадают в `dist` при сборке.

Микрофон работает только по HTTPS — домен `*.pages.dev` это условие
выполняет.

## Платформа

MVP — PWA. Захват звука изолирован за интерфейсом `AudioSource`
(`src/audio/AudioSource.ts`), поэтому при переходе на нативную обёртку
(Capacitor: `AVAudioSession .measurement` на iOS, `AudioSource.UNPROCESSED` на
Android) DSP и UI не меняются — подставляется другая реализация интерфейса.

## Что нужно проверить руками на телефоне

Автотесты проверяют математику, но не устройство. На iPhone (Safari,
установленная PWA) и на любом Android (Chrome) нужно пройти по списку —
от результата зависит, остаёмся ли мы на вебе:

1. **Экран «Диагностика», обработка.** `track.getSettings()` должен показать
   `echoCancellation`, `noiseSuppression`, `autoGainControl` выключенными.
   Если браузер их не сообщает — смотрите пункт 3.
2. **Частота дискретизации.** Должна совпадать с аппаратной (обычно 48000).
3. **Срез верха.** Подайте розовый шум и нажмите «Проверить (5 с)». На части
   iPhone системные режимы микрофона режут всё выше ~8 кГц — если срез
   найден, веб-захват на этом устройстве непригоден и нужен план Б.
4. **Стабильность уровня (проверка AGC).** Дайте розовый шум и нажмите
   «Проверить (10 с)» в карточке «Стабильность уровня». Сдвиг больше 3 дБ при
   ровном сигнале — это автоусиление: спектр будет выглядеть правдоподобно, а
   уровни врать. Браузер при этом может утверждать, что AGC выключен.
5. **Запись WAV.** Запишите 10 с и посмотрите файл в редакторе.
6. **USB-микрофон.** Подключите измерительный микрофон и проверьте, виден ли
   он в списке входов и отдаёт ли два канала (для фазы 6).
7. **Производительность.** Карточка на экране диагностики: не меньше 30 FPS,
   память не растёт за 30 минут.
8. **Экран не гаснет** во время замера (Wake Lock; на iOS до 16.4 его нет).
